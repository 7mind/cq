## Design (locked from ledger T2150/T2134/D334)

1. **Journal** (`@cq/ledger` new `guardedRebaseContinuation.ts`): durable
   journal under `registryRoot/guarded-rebase/<sha256(taskId\nhandleToken\noperationId)>/journal.json`
   written under `withManagedWorktreeEffectLock`. Binds task, handle
   token/fingerprint, repo root/id/commonDir, worktree, branch/ref,
   baseCommit, oldResultCommit (live tip at intent), ontoCommit,
   rebasedStartCommit, requestDigest, conflict receipts, outcome
   (clean|conflicted), exactTip, timestamps. States: intent → (rebase-stopped
   with observed conflict state) → finalized. Opaque reference
   `cq-guarded-rebase:v1:<requestDigest>`. Exact replay returns same
   reference; changed-payload reuse (digest mismatch) rejects; restart
   reconciles (finalize from live state + durable continuation receipts).
   exactTip = outcome clean AND patch-id(base..old) == patch-id(onto..rebased).
2. **CLI**: `cq gate git-effect --operation rebase` gains optional
   `--operation-id`; when present the journaled guarded path runs and stdout
   carries `CQ_GUARDED_REBASE_REFERENCE=<ref>` on finalize. Absent → legacy.
3. **Prepare** (ledger-mcp dispatchCapability): new sibling param
   `guardedRebase`; requires codex surface + implement-worker + reprepareOf.
   Caller-injected `input.guardedRebaseLineage` rejects (like
   inheritedGitReceipts). Verify: journal finalized; coordinates == prior AND
   current binding; prior receipts resolve to oldResultCommit;
   input.baseCommit == ontoCommit; input.startingCommit == rebasedStartCommit;
   live ref tip == rebasedStartCommit; input.priorResultCommit ==
   oldResultCommit (only exemption). Attach `guardedRebaseBridge` to
   gitEffectBinding (persisted, digest-covered), inject closed
   `guardedRebaseLineage` into input. Later corrections: bridge carried from
   prior row binding, re-verified, lineage re-injected; inheritance covers
   post-rebase receipts only (empty inherited requires startingCommit ==
   rebasedStartCommit).
4. **Output**: closed `gitLineage` discriminant `{kind:"guarded-rebase",
   guardedRebase, ontoCommit, rebasedStartCommit, exactTip}`; guarded arm
   reports only the fresh post-rebase suffix (empty iff resultCommit ==
   rebasedStartCommit && exactTip). Ordinary arm: no gitLineage, non-empty
   chain. filesTouched derived from ontoCommit..resultCommit (= dispatch base).
   Store-time validation rejects omission/substitution/pre-rebase receipts/
   mode spoofing; schema conditionals keep ordinary minItems=1.
5. **Role md** Step 0: guarded arm requires baseCommit == ontoCommit, HEAD ==
   startingCommit == rebasedStartCommit; initial bridge priorResultCommit ==
   oldResultCommit exact exemption; WIP-skeleton/new-receipt exemption only in
   server-resolved exact-tip mode. Regenerate catalogues.
6. **Tests**: new `packages/ledger/test/guardedRebaseContinuation.test.ts`
   (journal lifecycle: clean, conflict, replay, changed-payload, restart,
   nonterminal, foreign/stale). D334 test → plain, full lifecycle with the
   reference. Schema tests + shared backend codec tests extended. Inventory
   entry + annotation removed.

exact-tip mode). Persist the verified bridge through dispatch Git binding,
prepare digest, every backend, and parent-gate state.
