# G81 remote ownership — operator notes

`cq serve` is the sole PostgreSQL owner. Project checkouts use
`backend = "remote"` plus a committed `serverUrl`. Secrets stay in the
environment. Public `backend = "postgres"` is retired.

## Start throwaway PostgreSQL and the hub

```
# from nix/pkg/cq-ledgers
podman compose -f dev/docker-compose.postgres.yml up -d
export CQ_LEDGER_PG_URL=postgres://cq:cq@127.0.0.1:5432/cq_test
export CQ_SERVE_TOKEN=ordinary-token
export CQ_SERVE_ADMIN_TOKEN=admin-token-different
cq serve --pg-url "$CQ_LEDGER_PG_URL" --token "$CQ_SERVE_TOKEN" \
  --admin-token "$CQ_SERVE_ADMIN_TOKEN" --port 5190
```

A second `cq serve` against the same DSN is refused by the advisory lock.
Lock-connection loss fail-stops the owner.

Ordinary MCP: `/p/<projectKey>/mcp` with `CQ_LEDGER_REMOTE_TOKEN` (same value
as `--token` / `CQ_SERVE_TOKEN`).
Admin MCP: `/p/<projectKey>/admin/mcp` with `CQ_SERVE_ADMIN_TOKEN` /
`CQ_LEDGER_REMOTE_ADMIN_TOKEN`.
The admin token must differ from the ordinary and management tokens.

## Configure a checkout

```
[ledger]
backend = "remote"
serverUrl = "http://127.0.0.1:5190"
projectId = "my-project"
```

```
export CQ_LEDGER_REMOTE_TOKEN=ordinary-token
export CQ_LEDGER_REMOTE_ADMIN_TOKEN=admin-token-different   # migrate/backup/restore/reset/erase only
```

`.mcp.json` stays `{"mcpServers":{"ledger":{"command":"cq","args":["mcp"]}}}`.
`cq mcp`, `cq web`, and `cq tui` without `--mcp-url` launch against that origin.
Direct HTTP (`--mcp-url http://127.0.0.1:5190/p/<key>/mcp`) is the primary
remote transport; `cq mcp` is the stdio proxy for spawn-style clients.

Routine commands use the ordinary token:

```
cq predicates
cq counts
cq stats
cq advance-gate
cq log put ./note.md --dest logs/note.md
```

## Admin operations

- `cq migrate --to remote` reads the local xdg dump, imports with
  `intent=migrate-empty`, then writes `backend=remote`. Requires
  `CQ_LEDGER_SERVER_URL` and `CQ_LEDGER_REMOTE_ADMIN_TOKEN`.
- `cq backup` / `cq restore` exchange the existing `.cq` dump through admin
  export/import. Restore uses `intent=restore-replace-confirmed` after local
  confirmation. Re-run the same `operation_id` after a lost response.
- `cq reset` / `cq erase` call admin `reset_project` / `erase_project` with a
  client `operation_id`. Auth or transport failure is reported as NOT
  reset/erased / outcome-unknown, never as success.

```
export CQ_LEDGER_SERVER_URL=http://127.0.0.1:5190
cq migrate --to remote
cq backup
cq restore --yes
cq reset --yes
cq erase --yes
```

`cq migrate --to postgres` is refused; use `--to remote`.

## Frontends

`cq web` and `cq tui` switch projects through the hub project list. Deep-link
`?project=<key>` on the web UI. Neither frontend opens PostgreSQL.

## Live tests

Hub-internal suites still gate on `CQ_TEST_PG_URL` (throwaway DSN, not a
public checkout backend):

```
export CQ_TEST_PG_URL=postgres://cq:cq@127.0.0.1:5432/cq_test
cd nix/pkg/cq-ledgers && bun test
```
