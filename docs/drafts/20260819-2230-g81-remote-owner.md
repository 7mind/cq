# G81 remote ownership — operator notes

`cq serve` is the PostgreSQL owner. Project checkouts use `backend = "remote"` plus a committed `serverUrl`. Secrets stay in the environment.

## Start the hub

```
cq serve --pg-url "$CQ_LEDGER_PG_URL" --token "$CQ_SERVE_TOKEN" \
  --admin-token "$CQ_SERVE_ADMIN_TOKEN" --port 5190
```

Ordinary MCP: `/p/<projectKey>/mcp` with `CQ_LEDGER_REMOTE_TOKEN`.
Admin MCP: `/p/<projectKey>/admin/mcp` with `CQ_SERVE_ADMIN_TOKEN` / `CQ_LEDGER_REMOTE_ADMIN_TOKEN`.
The admin token must differ from the ordinary and management tokens.

## Configure a checkout

```
[ledger]
backend = "remote"
serverUrl = "http://127.0.0.1:5190"
projectId = "my-project"
```

```
export CQ_LEDGER_REMOTE_TOKEN=...
export CQ_LEDGER_REMOTE_ADMIN_TOKEN=...   # migrate/backup/restore/reset/erase only
```

`cq mcp`, `cq web`, and `cq tui` without `--mcp-url` launch against that origin.
`cq predicates`, `cq counts`, `cq stats`, `cq advance-gate`, and `cq log put` use the ordinary token.

## Admin operations

- `cq migrate --to remote` reads the local xdg dump, imports with `intent=migrate-empty`, then writes `backend=remote`. Requires `CQ_LEDGER_SERVER_URL` and `CQ_LEDGER_REMOTE_ADMIN_TOKEN`.
- `cq backup` / `cq restore` exchange the existing `.cq` dump through admin export/import. Restore uses `intent=restore-replace-confirmed` after local confirmation.
- `cq reset` / `cq erase` call admin `reset_project` / `erase_project` with a client `operation_id`. Auth or transport failure is reported as NOT reset/erased / outcome-unknown, never as success.

Public `backend = "postgres"` is retired. PostgreSQL is private `cq serve` state.
`cq migrate --to postgres` is refused; use `--to remote`.

A second `cq serve` against the same DSN is refused by the advisory lock.
Lock-connection loss fail-stops the owner.
